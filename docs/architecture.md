# 1.2 任务与恢复

插件不提供独立 HTTP 服务。管理桥只读写任务，模型执行依附公开 maintenance / RECONCILE 父调用；一个进程内同时只有一个执行槽。页面离开不发送取消请求。

| 状态 | 含义 |
| --- | --- |
| queued | 已持久化，等待完整执行窗口 |
| running | 已保存当前样本执行意图 |
| scoring | 有效样本已保存，等待离线评分 |
| paused | 无效样本、请求失败、身份变化或结果不确定，需要人工处理 |
| completed | 已完成判分或形成有明确边界的指纹结果 |
| stopped | 用户已停止，保留已有证据 |
| deleting | 删除标记已保存，维护回调可继续未完成清理 |

tasks 保存冻结计划、身份投影、已接受的样本引用、所有尝试摘要和最终评分。samples 以任务 ID 与尝试序号保存有界原始结果，queue 保存有界索引。旧 history/details 原样保留，新任务不混入旧统计。

发请求前，任务和索引必须均保存成功。收到结果后先保存确定的样本 key，再更新任务进度和索引。恢复时检查 pending 样本是否存在：存在则接着校验或评分，不再调用模型；不存在则保存 uncertain 尝试并暂停。用户继续只补未接受的题，不重复已有有效样本。

管理写入和维护阶段的读写使用短临界区，模型等待期间不占管理锁；状态写入携带宿主版本。停止信号同时落盘并通知执行槽。调用取消后，无法确认落盘的结果回到上述恢复规则。清理先保存 deleting 标记，再逐个删样本、任务和索引；缺失索引目标在维护时收敛。

每题都检查身份与固定资源摘要，评分前也核对资源。稳定上游身份一致时允许凭据版本刷新；没有稳定身份时要求版本一致。冻结的基线、题库或语境改变后，不将旧样本交给新算法继续评分。

数字样本有效性与 HTTP/流完成分别处理。模型事件只累计有界正文、用量和终态，不保留整轮 reasoning/wire。完整终态和原算法样本校验均通过，才计入有效样本。指纹最终评分固定 strict-three-v1。

私有状态无法提供跨命名空间业务事务，因此恢复以已提交记录为准，不能确认消费的请求不自动重放。测试专门覆盖意图落盘、结果落盘后任务提交失败，以及该窗口中的停止和删除。
