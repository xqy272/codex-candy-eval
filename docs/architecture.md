# 批次调度、UI 与恢复

插件不提供独立 HTTP 服务。管理桥只读写任务，模型执行依附公开 maintenance / RECONCILE 父调用；实例内共享 1–4 个执行槽，默认 2 个；每个账号跨批次最多一个在途请求。旧同步接口保留独立互斥保护，不与后台工作同时启动。页面离开不发送取消请求。

1.2.1 起，鹈鹕绘图的整次模型调用最多 600 秒，糖果与指纹保持 150 秒；管理阶段声明 620 秒、维护阶段声明 630 秒。每次发出请求前，按当前测试类型检查剩余预算是否足够覆盖完整调用加 10 秒收尾，不把首个响应事件视为完成或重新计算无限等待。插件主动达到时限会关闭流、保存请求 ID 和带来源的时限诊断、暂停任务，不自动重发；上游未返回最终 usage 时保留缺失，不填零。私有状态 schema 保持不变。

| 状态 | 含义 |
| --- | --- |
| queued | 已持久化，等待完整执行窗口 |
| running | 已保存当前样本执行意图 |
| scoring | 有效样本已保存，等待离线评分 |
| paused | 无效样本、请求失败、身份变化或结果不确定，需要人工处理 |
| completed | 已完成判分或形成有明确边界的指纹结果 |
| stopped | 用户已停止，保留已有证据 |
| deleting | 删除标记已保存，维护回调可继续未完成清理 |

tasks 保存冻结计划、身份投影、已接受的样本引用、所有尝试摘要和最终评分。samples 以任务 ID 与尝试序号保存有界原始结果，queue 保存有界索引。旧 history/details 原样保留，新任务不混入旧统计。

发请求前，任务和索引必须均保存成功。收到结果后先保存确定的样本 key，再更新任务进度和索引。恢复时检查 pending 样本是否存在：存在则接着校验或评分，不再调用模型；不存在则保存 uncertain 尝试并暂停。用户继续只补未接受的题，不重复已有有效样本。

管理写入和维护阶段的读写使用短临界区，模型等待期间不占管理锁；状态写入携带宿主版本。停止信号同时落盘并通知执行槽。调用取消后，无法确认落盘的结果回到上述恢复规则。清理先保存 deleting 标记，再逐个删样本、任务和索引；缺失索引目标在维护时收敛。

每题都检查身份与固定资源摘要，评分前也核对资源。稳定上游身份一致时允许凭据版本刷新；没有稳定身份时要求版本一致。冻结的基线、题库或语境改变后，不将旧样本交给新算法继续评分。

数字样本有效性与 HTTP/流完成分别处理。模型事件只累计有界正文、用量和终态，不保留整轮 reasoning/wire。完整终态和原算法样本校验均通过，才计入有效样本。指纹最终评分固定 strict-three-v1。

私有状态无法提供跨命名空间业务事务，因此恢复以已提交记录为准，不能确认消费的请求不自动重放。测试专门覆盖意图落盘、结果落盘后任务提交失败，以及该窗口中的停止和删除。


## 批次的创建与恢复

`batches` schema 1 保存批次、索引及实例并行设置；旧五个命名空间的声明原样保留。批次请求冻结账号集合、模型、强度、语境、次数和绘图输出版本。子任务 ID 由批次 ID、账号序号与重复序号确定；相同 ID 的参数改变返回冲突，丢失提交响应后重试相同请求不会增加任务或重新抽题。

创建先登记批次 ID，避免产生无法列出的孤立批次；再把全部冻结计划保存在 ready=false 的批次记录，再逐项保存任务与索引，最后标记 ready 并移除临时计划。维护不执行尚未 ready 的子任务；创建中断后显式重试同 ID 完成提交。准备计划仅内部保存，不由批次列表返回。整个过程只使用宿主 CAS 状态 API，无跨命名空间事务假设。

批次保留 stopped 与 stoppedAccounts 持久范围。停止先提交范围，再通知每个对应 worker 并更新子任务；如果中途退出，下一轮继续收敛剩余任务。已完成结果保留；被停止的范围拒绝恢复。普通失败或无效样本不停止其他账号。

## 共享调度器

maintenance 使用 JoinSet 同时等待多个请求。短 admission 锁保护状态读取、意图提交、全局槽位及账号占用，模型网络等待不持有该锁。槽位作用域覆盖所有批次；worker 使用 RAII 释放自己的槽位，任务顺序随保存索引轮转。

一个样本完成即先保存自己的结果、更新任务，然后立即补入可调度的下一份请求，不对一轮所有账号设置完成屏障。维护剩余预算不足以覆盖当前测试完整窗口时跳过该项；可继续选择窗口较短的任务。状态故障时等待已经启动的兄弟请求收尾，不因为另一个任务保存失败而主动丢掉其输出。

每个 worker 有独立取消信号与内存 Progress。进度只从实际 execute_stream/读取事件产生，报告与列表在读取时附加；不把逐 chunk 进度写入数据库。重启后进度不存在，不能按旧计时虚构仍在运行，使用持久意图恢复规则。

## 展示合同

1.4.2 继续使用 @codex-proxy/ui 0.9.1 的公开组件、样式与构建插件。宿主桥注入完整主题并同步变化，已连接页面不重设默认主题；独立预览才调用 createTheme/applyTheme。字体以正式管理资源声明并由宿主组装，不能在构建 CSS 中预先内嵌 data URL。标题由宿主呈现，插件内容不重复页面标题。

App 组织导航和工作区。RequestPanel、AccountPicker、ResultWorkspace、BatchResults、HistoryList、TestResult、ArtworkView 和 ArtworkComparison 分别负责配置、目标、结果导航、总览、记录、专属结果、预览和对比。自定义 CSS 负责布局与业务展示，视觉角色来自官方主题变量。

测试页的批次总览显示一条时间：已完成且各冻结任务都有可信结束时刻时，取最后一项任务的更新时间；仍未全部完成时使用批次发起时间，已完成但无可信时刻时显示未记录。记录表的时间仍是批次发起时间。账号结果沿用检测发起时刻，日期和时刻一起加粗，与测试页批次时间共用显示组件。批次结果弹窗只显示状态、冻结条件和账号列表。

多账号默认总览，单账号提交后直接打开结果弹窗，刷新只恢复总览。历史可从具名账号直达详情，也可先开总览。详情中可切换同批次账号，返回键、关闭图标或 Escape 先回多账号总览，关闭总览恢复记录的原入口焦点。退场完成后再清除详情状态，快速重开保留新的打开意图。查看结果不改变下一次勾选。执行状态与测试结论单独筛选，读取失败保留已有结果。

遮罩铺满插件 iframe；只调整面板的起点和可用高度。弹窗存在期间使用 IntersectionObserver 读取当前 frame 在宿主滚动容器内的交集，按本地坐标定位面板，无法读取交集时回退到宿主提供的 `--plugin-viewport-height`。正文独立滚动，页脚保持在可见区；不需要读取父窗口 DOM。多层弹窗共享同一可见区观测。

AnswerBody 使用官方 ZMarkdown 的清洗与 Shadow DOM 样式，代码块和原始回答不改写。阅读视图仅兼容模型常见的闭合粗体前空白，保护公式定界符避免 Markdown 先行吞掉反斜杠，再用受限 KaTeX 输出 MathML；不使用外部公式字体或脚本。结果主区展示回答和尝试，侧栏展示请求条件、耗时与用量，窄屏按顺序堆叠；题目、指令和请求 ID 直接显示，完整诊断 JSON 折叠。用量只汇总上游返回的有效数值，缺失保留提示。复制和原文模式始终使用存储的原始字节。糖果次数按钮用结论短标签，详情随所选次数切换。

工作台表单、当前批次和历史报告分离；CPR 私有状态 batches/workspace 保存草稿、账号选择与未确认提交 ID，只保存 Key ID。宿主 iframe 为不透明来源，不依赖 localStorage。提交先保存幂等编号，再创建后台批次；多个页面写入同一实例草稿时使用版本比较，过期页面停止提交并提示刷新。后台冻结计划是结果依据。历史筛选和工作台草稿互不覆盖；轮询使用稳定组件 key，已结束样本按唯一尝试 key 缓存，不反复清空详情和焦点。

糖果逐次保留原回答与有效分母；指纹展示三样本状态和原算法候选排名；绘图新批次通过 svg-v1 明确选择新题，legacy-animation-v1 及旧任务保留旧题。源码和算法基线不改动。SVG 经 XML 验证与 DOMPurify 清洗，再放入 image data URL；HTML、脚本、外链及嵌入节点不执行。预览失败与生成失败是不同状态。重新预览、复制及已有作品对比不调用模型。
