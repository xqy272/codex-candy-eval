# codex-candy-eval

CPR 原生模型测试插件，版本 **1.4.2**。使用 CPR 官方 UI 组件，随宿主主题同步配色、字体、圆角和控件密度；糖果题、模型指纹和画鹈鹕各有自己的结果工作区。批次状态旁显示时间，账号弹窗直接展示回答和请求详情。选择账号后提交一个批次，离开页面后由 CPR 继续执行。Linux x86_64 安装包包含程序、管理页、字体和固定检测资源，无需独立服务。

## 安装与升级

本版构建文件为 `dist/cloudops.codex-candy-eval-1.4.2-x86_64-unknown-linux-gnu.tar.gz` 及同名 `.sha256`。从 [v1.4.2 Release](https://github.com/xqy272/codex-candy-eval/releases/tag/v1.4.2) 下载后，上传至 CPR 插件管理并核对摘要，打开“模型测试”。

要求 Linux x86_64、glibc 2.28+。宿主声明为 `>=3.43.1, <3.45.0`，组件对齐 CPR 3.44.0 的 UI 0.9.1；实际验收版本见 [验收记录](docs/verification.md)。遮罩覆盖插件页面，弹窗面板随宿主可见区域调整。旧宿主保留使用此前适配版本。

已有用户在**原实例切换版本**，保留插件 ID `cloudops.codex-candy-eval`，不要删除实例或清空私有状态。升级前结束活动请求，备份数据库与应用数据，并按宿主提示检查清单。1.4.2 全部私有状态声明与 1.4.1 相同，无需新增迁移。已有报告、暂停任务、冻结题目及样本继续可读；升级不自动重发无法确认消费的请求。旧同步记录与旧独立任务继续在“记录”查看。

需要退回旧版时，停止任务并使用升级前成套备份；跨版本原地降级未经验证。

## 使用

1. 切换“糖果题 / 模型指纹 / 画鹈鹕”，设置常驻显示的模型、推理强度、请求语境和 Key。首次进入不自动选择账号或模型；Key 始终使用可搜索的完整选择框，唯一可用 Key 自动选中。
2. 搜索并选择账号，核对计划请求数后点击开始。糖果每账号可测 1、3、5 次，答案归在同一账号下；指纹每账号三样本，绘图一次。一次点击对应一个持久批次，不是散落的结果卡片。
3. 左侧勾选只决定下一次检测目标。“本批次”在状态旁显示发起时间，全部完成后显示最后一项任务的完成时间。多账号可从总览打开账号结果，单账号提交后直接打开结果弹窗，刷新后可从总览重新打开。三类测试保留各自条件和上次批次，修改表单不会改写冻结结果。长账号名称可悬停查看全文，手机账号选择可展开并收起。
4. 在“记录”分别按测试、账号、执行状态、测试结论和日期筛选。点账号名称直达检测结果，也可以先打开批次总览。多账号的结果弹窗里可以切换账号；返回批次后再关闭，回到原来的记录和筛选。
5. “检测结果”顶部显示账号、结论和加粗的检测时间；主要区域展示回答、尝试、指纹排名或作品，旁边列出请求条件、耗时与用量。题目和请求 ID 可直接查看，只有完整诊断 JSON 折叠。普通复制/导出提供可读摘要；下载或剪贴板受限时可选中回退文本复制。

回答默认按 Markdown 阅读，支持标题、列表、表格、代码及 `\(...\)`、`\[...\]`、`$$...$$` 公式。使用官方 Markdown 组件清洗内容，公式在本地生成 MathML，不加载外部脚本或字体；代码块保留原样。“原文”和复制始终保留最初返回的完整文本，阅读视图的格式兼容处理不改变判分或存储内容。糖果多次回答的按钮只显示次数和结论，不再塞入带格式的回答摘要。

开始按钮附近显示缺少的条件；提交结果未确认时，“核对提交状态”复用原批次编号，不创建新消费。同步读取失败保留已有结果并提供重新读取。作品支持放大、代码和下载，A/B 对比的第三份作品需明确选择替换位置；这些查看操作不发模型请求。

草稿、账号选择和待确认批次编号保存在 CPR 的插件私有状态中，刷新后恢复，不依赖 iframe 内被禁用的浏览器本地存储。只保存 Key ID；同一插件实例的多个页面发生草稿版本冲突时，提示刷新读取，防止覆盖未确认的提交。

账号名称为空或仅含空白时显示邮箱，邮箱也为空时显示稳定账号 ID；列表、记录筛选和结果页都保留可识别的账号标签。搜索支持名称、邮箱和账号 ID。启停状态直接使用 CPR 返回值，显示回退不会修改账号或历史记录。

| 测试 | 结果与边界 |
| --- | --- |
| 糖果题 | 使用原题，标准答案为独立数字 **21**。展示真实回答和正确/有效次数，执行失败独立计数，不算答错 |
| 模型指纹 | 固定配套题库抽三题；完整终态及原算法数字校验通过后形成参考库候选排名，概率不代表模型身份证明 |
| 画鹈鹕 | 默认“标准 SVG v1”，要求完整独立 SVG，直接预览、查看代码、复制、下载；可对比两份已有作品，不自动评分 |

旧版 HTML 动画题保留原版本，可显式选择。旧任务续测沿用冻结原题，不把原题悄悄改成 SVG。旧 HTML 或不完整 SVG 无法预览时明确说明“作品已生成但无法预览”，保留原文；不执行模型生成的脚本或请求外部资源。

## 请求与并行

默认 **简洁请求** `simple-v1`，保留题目所需指令与 user 正文。可显式选择固定 **Codex 上下文 v1**；它包含较长 CLI 指令和工具声明，工具执行关闭，不宣称复制完整真实 Codex 客户端。未指定推理强度时省略该字段，继承宿主/上游默认；界面选项不保证每个模型都支持。

实例默认最多同时执行 **2 个不同账号**，可选 1–4；已有活动检测时不能改变全局上限。同一账号跨批次仍最多一个在途请求，账号内指纹样本逐题执行。某个槽位完成后独立保存并补入下一题，不等待其他慢账号。该数值只是插件上限，实际 Key/账号并发、额度、身份、认证与出口仍由 Core 管理。

测试消耗所选账号额度。插件不自行读取 OAuth、直连上游凭据、换账号或改变出口；宿主可能内部重试，计划调用数不等于上游 attempt 总数。

## 运行、停止与补测

工作区显示由实际事件得出的请求阶段、运行时长、最近事件时间、正文大小及有界片段；没有正文不显示“正在生成文字”，没有最终 usage 不补零。排队时间与实际运行时间分开。

绘图每次最多等待 **600 秒**，糖果与指纹 **150 秒**；维护预算 630 秒，每次开始前预留完整等待窗口与 10 秒保存余量，不缩短后排请求时限。宿主维护轮次之间可能需要等待约 30 秒。插件必须保持启用。

“停止此账号”覆盖本批次该账号尚未结束的所有次数；“停止本批次”覆盖所有账号。停止范围先落盘，再通知各活动流，其他账号/批次和已完成结果保留。停止后的范围不能继续，需要新建检测。

失败保留已有有效样本并等待处理；“补测 N 个样本”只补缺失/无效部分，沿用原计划，单任务最多九次尝试。评分失败可以仅重新分析，不发模型请求。结果不确定时不自动重发，手动补测需要再次明确确认可能重复消耗。上游身份、检测器或参考资源改变时要求新建检测。已保存结果可以恢复评分；只有意图、没有可靠结果时标记 uncertain。

## 存储边界

最多 16 份未结束子任务（包括等待处理），最多保留 100 份任务、约 12 MB 样本和 100 份批次元数据，优先淘汰已结束旧任务，保护未结束任务。糖果重复次数占用对应子任务数；指纹三样本属于同一子任务。每份回答正文最多 48 KiB，样本分别存取；活动正文预览最多 4096 字符，不把大流全部写入状态。批次元数据与子任务独立淘汰，缺失时明确提示部分记录已淘汰。旧 history/details 保留边界不变。

不合成“健康分”，不自动禁用或移组账号，也没有新增定时检测。

## 构建与验证

需要 Rust 1.99.1、C 工具链、Node.js 24+ 与 CPR 官方 `cpr-plugin` 打包 CLI。

```bash
git clone https://github.com/xqy272/codex-candy-eval.git
cd codex-candy-eval
cargo +1.99.1 fmt --manifest-path backend/Cargo.toml -- --check
cargo +1.99.1 clippy --manifest-path backend/Cargo.toml --all-targets --locked -- -D warnings
cargo +1.99.1 test --manifest-path backend/Cargo.toml --locked
npm --prefix frontend ci
npm --prefix frontend run build
npm --prefix frontend run test:ui
python scripts/verify_sources.py
export PLUGIN_CLI=/path/to/cpr-plugin
python scripts/build.py --target x86_64-unknown-linux-gnu
```

脚本从自身路径定位工程，使用锁文件、验证固定资源，再通过官方 CLI 打包并独立检查。交叉编译需配置目标工具链与链接器。安装包位于 dist，不进入 Git。

真实宿主、受控上游和页面测试见 [integration](integration/README.md)，持久化与恢复规则见 [架构说明](docs/architecture.md)，验证范围和边界见 [验收记录](docs/verification.md)。CI 模板在 ci/github-actions.yml，尚未启用。
